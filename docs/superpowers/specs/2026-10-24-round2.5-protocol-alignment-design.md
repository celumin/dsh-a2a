## 1. 为什么要改（纠正后的根因）

2026-10-22 的结论是"`a2a_send` 按 v0.3 探测 `agent.json`，网关 404"。复核源码后，这个结论是错的：`A2aClient.card()` 自 v0.1.0 起就是 `agent-card.json` 优先、`agent.json` 回退（`src/client.ts:143-144`）。

真实缺陷有四处，都在客户端：

1. **卡片 URL 丢失 base path**：`cardUrl` 是 `origin + wellKnown`（`src/client.ts:85`）。target 为 `http://gw:9090/a2a/pi-gw-agent` 时请求 `http://gw:9090/.well-known/agent-card.json`，而网关只在 `/a2a/{id}/.well-known/agent-card.json` 挂载。
2. **RPC URL 多一个尾斜杠**：`rpcUrl` 为 `path + '/'`（`src/client.ts:79-84`），发出 `POST /a2a/{id}/`；网关注册的是 `POST /a2a/{agentID}`（`a2a-way/internal/bridge/handlers.go:131`，chi，无 `RedirectSlashes`），匹配不上。
3. **method 名写死**：`send()` 固定 `message/send`（`client.ts:187`）、`sendStream()` 固定 `message/stream`（`client.ts:242`）；Pi 只认 `SendMessage`/`GetTask`（`pi-a2a/extensions/net.ts:368-371`），故 `-32601`。
4. **报文形状只认 v0.3**：即使方法名改对，v1.0 的 ProtoJSON 也不一样——`SendMessage` 返回 `{ "task": {...} }`（`net.ts:433`），状态是 `TASK_STATE_*`（`net.ts:397`），part 用成员名判别（`{ text }`，无 `kind`，`net.ts:589`）。`send()` 直接强转 `A2aTask`、`isTerminal()` 读 `task.status.state`（`client.ts:212-225, 372`），第一跳就会 TypeError 或永不到终态。网关把上游响应体原样透传（`bridge/forward.go:700` 的 `w.Write(body)`），所以这条路径**必然**命中。

DSH agent 当年"自行降级"绕过的是 1+2+3（手工拼 `POST /a2a/{id}` 并用 `SendMessage`），而且它当时也不需要解析 v1.0 的响应体。

## 2. 目标与非目标

**目标**

- target 的三种形态（根地址 / 卡片 URL / `a2a/{id}` 代理地址）都能自己找到卡片与正确的 RPC 端点。
- 按卡片协商 v1.0 / v0.3 的方法名，并把两种报文的形状归一，**内部 `A2aTask` / `Message` / `TaskEvent` 模型保持不变**。
- 工具输出让模型看得见"这个错误该不该重试"。
- README 能让没参与开发的人从零配好。
- 以 `0.4.0` 发布到 npm，并推 fork 分支。

**适配边界（只做这四件）**

1. `SendMessage` 的 `{ task }` / `{ msg }` 解包；
2. `TASK_STATE_*` → 内部小写状态（未知值原样保留，**不当作终态**）；
3. part 缺 `kind` 时按成员判别；
4. `GetTask` 的 params 统一 `{ id }`。

**非目标**

- **不做 v1.0 流式事件适配**：不实现 `SendStreamingMessage`，不解析 `{ statusUpdate }` / `{ artifactUpdate }`；v1.0 目标一律走同步（见 §3.3）。
- 不改自身 server 的版本声明（仍 `0.3.0`）与入站方法集。
- 不在网关侧做 method 名转换（网关 method-agnostic）。
- 不修网关"`supportedInterfaces[].protocolVersion` 恒为 1.0"的问题（见 §6 风险；本轮只消费卡片）。
- 不新增 `agent.json` 别名（2026-10-24 已决，整项取消）。
- 不实现 mDNS（R3，等网关 P5）。
- **不做卡片发现的进程级缓存**（短 TTL 列为 0.5.0 候选，见 `docs/requirements.md` R7）。
- 不改 `metadata.kind` / `metadata.from` 的既有语义。

## 3. 设计

### 3.1 卡片发现

把 target 归一成 `{origin, path}`：去尾部斜杠；若 path 以 `/.well-known/` 开头（用户直接给了卡片 URL），path 置空。

候选按序尝试、去重，取第一个 2xx **且能解出服务地址**的响应：

1. `{origin}{path}/.well-known/agent-card.json`
2. `{origin}{path}/.well-known/agent.json`
3. `{origin}/.well-known/agent-card.json`
4. `{origin}/.well-known/agent.json`

**理由**：网关只在 `/a2a/{id}/` 挂卡片（候选 1 命中）；Pi 只在 origin 根挂卡片（候选 3 命中）；DSH 自身 server 在根挂两张（候选 1/3 命中）。候选 3/4 对网关只是多一次 404。

缓存：卡片结果缓存在 `A2aClient` 实例内。客户端按工具调用创建（`tools.ts:90-96`），所以**每次 `a2a_send` 会付 1–4 次发现 GET**，跨调用不共享。**0.4.0 不做进程级缓存**（避免 target 换卡后读到旧卡片）；短 TTL 缓存列为 0.5.0 候选，见 `docs/requirements.md` R7。

### 3.2 RPC 端点

**卡片里的服务地址优先，输入路径只作兜底**：

1. `supportedInterfaces[]` 中 `protocolBinding`（大小写不敏感）等于 `JSONRPC` 的第一条，其 `url` 是绝对 URL → 用它；
2. 否则顶层 `url` 是绝对 URL → 用它；
3. 否则 `{origin}{path}`（**不加尾斜杠**；path 为空时用 `{origin}/`）；
4. 若最终 URL 的 path 以 `/.well-known` 结尾（卡片写错）→ 退回 origin 根。

**不追加尾斜杠**，POST 原样打到该 URL。

**同源约束**：卡片给出的 URL 必须与 target 同源；跨源默认拒绝，不发送 Bearer。理由：`headers()` 会把 token 打到每个请求上，而 allowlist 目前只检查用户输入的 target（`tools.ts:83-88`）。

逃生门：`clientAllowPatterns` 是**运维配置**，不是卡片自述——放行是运维的选择，不是卡片欺骗得逞。匹配规则是 **origin 精确匹配（scheme + host + port）**，不做前缀/通配。放行时记一条 WARN：`card endpoint cross-origin allowed by clientAllowPatterns`。

**拒绝文案 `card endpoint origin mismatch` 不包含卡片里的 URL**（避免回显不可信内容、也避免泄漏内部地址）。

### 3.3 method 协商

版本声明的取值顺序（全部来自已拉到的卡片）：

1. `supportedInterfaces[]` 中 JSONRPC 条目的 `protocolVersion`；
2. 顶层 `protocolVersions[]` 的首个；
3. 顶层 `protocolVersion`。

判定：声明以 `1.` 开头 → **v1.0**；以 `0.` 开头 → **v0.3**；其余情况进入 §3.3.1（默认版本）或 §3.3.2（降级）。

#### 3.3.1 默认版本（无声明 → v0.3）

**触发条件**：卡片取到了，但没有任何可用版本声明（缺失或无法解析）。
**行为**：按 **v0.3** 处理（`message/send` / `tasks/get`）。

理由：v1.0 的卡片有强制标记（`supportedInterfaces` + `protocolVersion`），缺失基本意味着旧实现；默认 v0.3 也保住既有行为。

> **本文档修正了 ROADMAP / requirements 早期版本"默认 v1.0"的笔误。** 那句把 `message/send` 误当成了 v1.0 的方法名；真实对应是 v1.0 → `SendMessage`，v0.3 → `message/send`。默认值因此从 v1.0 改为 v0.3。

#### 3.3.2 降级行为（取不到卡片 → 输入路径 + v0.3）

**触发条件**：四个候选全部失败（或没有候选能解出服务地址）。
**行为**：RPC 端点用 `{origin}{path}`（不加尾斜杠），版本按 **v0.3** 处理，不使用任何卡片派生的值。
**降级不改变报文内容**：`metadata.kind` / `metadata.from` 照常写入 `message`——降级只影响"用哪个端点、哪种方法"，不是"最小报文"。丢掉 `kind` 会让 Pi 只入库、不处理。
**可观测**：最终 RPC 失败时，detail 同时给出两侧信息，结构为
`RPC 失败：<rpc error>；卡片发现失败：试过这些 URL`（候选去重、不含 token）。只报"卡片没找到"会让用户不知道 RPC 错在哪。

> 与 §3.3.1 的区别：**卡片在、没版本** vs **卡片不在**。两者触发条件不同、行为相同、测试用例不同——必须分开测。

#### 3.3.3 方法表

| 操作 | v1.0 | v0.3 |
| ---- | ---- | ---- |
| 发送 | `SendMessage` | `message/send` |
| 流式 | **不启用**（即使卡片声明 `streaming: true` 也走同步） | `message/stream`（仅当 `streaming === true`） |
| 轮询 | `GetTask` | `tasks/get` |
| 取消 | `CancelTask` | `tasks/cancel` |

- **`GetTask` 的 params 不按版本分支**：两种版本都发 `{ id }`。fork 自己的 server 同时接受 `id` 与 `taskId`（`server.ts:471-473`），Pi 只读 `id`（`net.ts:438`）。
- **`CancelTask` 的 params 按版本分支**：v1.0 发 `{ id }`，v0.3 发 `{ taskId }`。

**流式只对 v0.3 启用**：网关只把 `method == "message/stream"` 当 SSE（`a2a-way/internal/bridge/handlers.go:585`），v1.0 的 `SendStreamingMessage` 会被当普通同步调用转下去。

**请求头**：RPC 请求带 `X-A2A-Version`，格式固定"主.次"——v1.0 发 `1.0`，v0.3 发 `0.3`（不写补丁号）。卡片 GET 不带版本头。现状硬编码 `0.3.0`（`client.ts:105`），严格实现会 400（fork 自己的 server 就会，`server.ts:278-285`）。

若对端因**卡片 GET 缺少版本头**而拒绝（非标准 server），视为卡片发现失败，走 §3.3.2 降级，不让链路卡死在发现阶段。

**不做静默换名重发**：对端 `-32601` 时原样报错，detail 里附"卡片声明 vX、已用方法 Y"，避免同一消息投递两次。

### 3.4 wire 形状适配

内部模型不变，适配只发生在 `A2aClient` 的收发边界。v1.0 是 ProtoJSON：oneof 用成员名承载、枚举用 `TASK_STATE_*`、part 用成员名判别；v0.3 是裸 Task + 小写状态 + `kind` 字段。

**入站归一（只有这四件）**

- 解包：`SendMessage` 的 `{ task }` / `{ msg }` → 裸 Task / Message；`GetTask` 返回裸 Task，两种都接受。
- 状态映射：`TASK_STATE_SUBMITTED|WORKING|COMPLETED|FAILED|CANCELED|REJECTED|INPUT_REQUIRED|AUTH_REQUIRED|UNSPECIFIED` → 内部小写值；**未知值原样保留，不当作终态**。轮询超时的错误信息必须说明这一点：`最后一次看到的状态是 <未知值>，客户端不识别，未当作终态`——否则用户分不清是 agent 卡住还是客户端不认识状态。
- part 判别：缺 `kind` 时按成员猜——有 `text` → text，有 `data` → data，有 `url` / `file` → file。
- 出站 params：message 结构两版一致不转换；`GetTask` 统一 `{ id }`；`CancelTask` 按 §3.3.3 分支。

**不做**：v1.0 的 SSE 事件（`SendStreamingMessage`、`{ statusUpdate }`、`{ artifactUpdate }`）。v1.0 一律同步。

**参考实现**：`pi-a2a/extensions/net.ts:433`（`{ task }`）、`:397`（状态枚举）、`:589`（part 无 `kind`）、`:438`（`params.id`）。

### 3.5 错误码可见化（R5）

客户端本来就没有自动重试，`A2aRpcError` 也已保留 `code` 与网关 message。本轮只把分类暴露给模型——`a2a_send` / `a2a_task_status` 失败时新增两个可选字段：

- `error_code`: number（`A2aRpcError.code`；HTTP 层错误为 `-1`）
- `retryable`: boolean

映射：`-32005` / `-32006` → `false`；`-32003` → `true`；其他码 → 两个字段都省略。message 原样保留（`远端 A2A 返回错误 <code>: <message>`）。

不引入任何自动重试。

### 3.6 文档（R4 / R6）

README 改写/新增：

- 配置入口是 `cordis.patch.yml` 的 `a2a` 行；patch 是**整体替换** `config`，不是深合并；旧 `a2a.json` 写法标注"已过时"。
- web 与 tui 两份可直接复制的示例；tui 显式写 `provider` / `model`。
- 密钥用 `env:A2A_TOKEN`，不写明文。
- web 面板的 base URL / Bearer 存浏览器 storage，不写进 profile。
- web 与 tui 同时运行的端口冲突、`context-sessions.json` 覆盖冲突。
- "名字一致性"小节：`peerName`、未来的 mDNS `name`、网关 `A2A_AUTH_TOKENS` 的 caller，三处必须一致；用现网真实名字举例（`dsh-agent-lenovo`、`pi-gw-agent`）。不一致的表现是"配了但永远不命中"。
- 示例里调用 Pi 这类"消息投递型" agent 用 `kind=request`（`kind=message` 只入库、不回 artifact，会得到空洞的成功）。

## 5. 测试计划

- **单测**（node，无网络）：URL 归一与候选去重、同源约束（origin 精确匹配、放行时 WARN、拒绝文案不含 URL）、method 表、状态映射（含未知值不终态与超时文案）、part 判别、错误码映射、`X-A2A-Version` 格式、降级时 detail 结构、降级后 `metadata.kind`/`from` 仍在报文中。
- **fixtures**：必须覆盖两种报文形状——v1.0 `{task}` 与 v0.3 裸 task；9 个 `TASK_STATE_*` + 一个未知值；part 有/无 `kind`。
- **两条规则分开测**：§3.3.1（卡片在、无版本）与 §3.3.2（无卡片降级）各自一个用例，断言不同的触发路径与错误文案。
- **冒烟**（扩展 `tests/smoke.mjs`）：卡片两种形态（顶层 `url` / 只有 `supportedInterfaces`）都能解析出端点。
- **e2e**（需要环境）：`scripts/e2e-round2.5.sh` 起 NATS + 网关 + Pi `be-daemon`，断言链路、`kind=request` 轮询拿到 artifact、`-32005` / `-32006` / `-32003` 三态。

## 6. 风险

- **网关卡片自相矛盾**：`supportedInterfaces[].protocolVersion` 恒为 `1.0`，但顶层 `protocolVersions` 保留注册方声明（`presenter.go:86-95`）。协商按接口条目优先，故经网关一律 v1.0——把 v0.3 上游挂到网关后面会被用 `SendMessage` 调用。本轮不修网关，只在 README 记一条。
- 卡片 `url` 不可信 → 同源约束 + 兜底输入路径；错误信息不回显卡片 URL。
- 适配层是新增面积 → 用 fixtures 锁住两种形状，避免"只测通一路"。
- `0.4.0` 与上游 `0.3.x` 分叉 → README 写明关系；上游修复后优先切回。

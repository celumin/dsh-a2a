# dsh-a2a 0.4.0（Round 2.5）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `a2a_send` 经网关调用 v1.0 目标（Pi）全链路可用，并让端点选择、方法协商、错误分类可测、可解释。

**Architecture:** 把纯逻辑抽到两个新模块——`src/endpoint.ts`（target 归一、卡片候选、端点授权）与 `src/compat.ts`（版本协商、方法表、响应归一、错误分类）；`src/client.ts` 只做编排（发现 → 协商 → 收发 → 轮询），`src/tools.ts` 只做输出整形。所有网络行为通过 `fetchImpl` 注入，所有 WARN 通过 `logger` 注入，测试不需要起 DSH。

**Tech Stack:** TypeScript 5.6（ESM、`allowImportingTsExtensions`）、Node ≥20 全局 `fetch`、`node:assert` + 手写测试运行器、零新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-24-round2.5-protocol-alignment-design.md`

## Global Constraints

- 不新增运行时依赖；`src/protocol.ts` 保持零依赖（仅 `node:crypto`）。
- Node ≥ 20；ESM，相对导入带 `.ts` 扩展名。
- 版本号 `0.4.0`；不发 pre-release 后缀。
- 不引入自动重试。
- 跨源端点：默认忽略并回退；只有 `clientCardEndpointPatterns`（完整 URL 前缀、默认 `[]`、`*` 不生效）显式放行才采用并带 Bearer。
- 同源端点也要过 `clientAllowPatterns` 的路径作用域。
- WARN 只记 origin 与原因码，不记 path/query，不回显卡片 URL。
- 出站 message 形状保持不变（`role:"user"`、`kind:"message"`、`parts[].kind`）。
- 不做 v1.0 流式事件；流式仅在"卡片存在 + v0.3 + `streaming:true`"时启用。
- 错误信息里嵌入响应体时截断 2KB。

## Review Focus

实现时最容易错的输入，按可能性排序；每条都要有对应测试：

1. target 带 query/fragment → 必须报错，不能静默丢弃。
2. 跨源卡片端点 → 忽略并回退，且跨源 host **收不到任何请求**（含卡片 GET）。
3. 同源但路径越界（`/tenantA` target、`/tenantB` 端点）→ 同样忽略并回退。
4. 卡片取不到（降级）或 v1.0 但 `streaming:true` → 绝不能发流式方法。
5. 4xx 响应体是 JSON-RPC error → 保留 `code`，不能退化成 `-1`。
6. v1.0 的 `{ msg }` 响应与 `GetTask` 的 `{ task }` 包裹 → 不能崩。
7. 超时（非终态）→ 结构化错误（含最后状态与 `task_id`），不能是空 detail。

### Task 3: `client.card()` — 候选、重定向、预算、日志

**Files:**
- Modify: `src/client.ts:139-172`（`card()` 与 `normalize()`）
- Test: `tests/compat.mjs`（捕获服务端）

**Interfaces:**
- Consumes: `normalizeTarget` / `cardCandidates` / `decideEndpoint` / `versionOf`
- Produces:
  - `A2aClientOptions` 新增 `logger?: (level: 'warn'|'info', msg: string, fields?: Record<string, string>) => void`、`fetchImpl?: typeof fetch`、`cardEndpointPatterns?: readonly string[]`
  - `client.card(forceRefresh?)`：签名与"全部候选失败即抛错"的语义**不变**，错误信息列出候选与各自原因
  - `client.endpoint(): Promise<EndpointDecision>`：**不抛错**，发现失败时返回 `{ source:'input' }`（供工具层与测试使用）
  - private `ensureCard(): Promise<{ card?: AgentCard; decision: EndpointDecision }>`（Task 4 使用）

- [ ] **Step 1: 写失败测试**（起 `node:http` 假服务端）
  - 路径基址命中卡片（只服务 `/a2a/x/.well-known/agent-card.json`）→ `card()` 成功
  - 卡片 GET 返回 302 → 该候选失败，继续/报错，**不跟随**
  - 两次候选都 404 → `endpoint()` 返回 `{source:'input'}`，`card()` 抛错且错误信息含候选 URL；`logger` 收到含 `origin` 的 WARN（不含 path/query）
  - 跨源卡片端点：起**两个**假服务端，断言跨源 host 的请求计数为 **0**（连卡片 GET 都不去）
  - 候选 URL 不在 `clientAllowPatterns` 路径作用域内 → 该次 GET **不带 Authorization**（假服务端断言 header 缺失）
  - `fetchImpl` 注入生效：假 fetch 记录被调 URL 与 header

- [ ] **Step 2: 跑测试确认失败**

- [ ] **Step 3: 实现**
  - `normalize()` 改用 `normalizeTarget`，删除 `cardUrl`/`rpcUrl` 的旧推导。
  - `ensureCard()`：遍历候选，`redirect:'manual'`，每候选 `AbortSignal.timeout(Math.min(5000, remaining))`；3xx 记失败；2xx 解析 JSON，取 `url`/`supportedInterfaces`，`resolve` 相对 URL；候选不在 `clientAllowPatterns` 作用域内时不带 `Authorization`。
  - 结果缓存为 `{ card?, decision }`；`decision` 由 `decideEndpoint` 产出；`logger` 发 WARN（只带 `target_origin` / `card_origin` / `reason`）。
  - `endpoint()` 调 `ensureCard()` 后返回 `decision`（不抛错）；`card()` 调 `ensureCard()`，`card` 缺失时抛错并列出候选与原因（`triggerForceRefresh` 时忽略缓存）。
  - 卡片 GET **不带** `X-A2A-Version`（版本尚未协商）；`Authorization` 仅在候选落在 `clientAllowPatterns` 作用域内时带。

### Task 4: `send` / `sendStream` / `getTask` / `cancelTask` — 协商与适配接线

**Files:**
- Modify: `src/client.ts:174-360`
- Test: `tests/smoke.mjs`（改现有跨源用例 + 新增断言）

**Interfaces:**
- Consumes: `negotiateVersion` / `methodsFor` / `versionHeader` / `normalizeSendResult` / `normalizeState` / `partKind` / `classifyError`
- Produces: `A2aTimeoutError extends A2aRpcError`（`code=-1`，message 含最后状态与 `task_id`）；`getTask`/`cancelTask` 内部先 `ensureCard()`

- [ ] **Step 1: 写失败测试**
  - v1.0 假服务端：断言收到 `SendMessage`、URL 为卡片给的端点、`X-A2A-Version: 1.0`；返回 `{task:{status:{state:'TASK_STATE_COMPLETED'},artifacts:[{parts:[{text:'ok'}]}]}}` → `sendForText` 得到 `ok`
  - v0.3 假服务端：断言 `message/send`、`X-A2A-Version: 0.3`
  - 卡片 `capabilities.streaming:true` 且 v1.0 → 断言**没收到** `SendStreamingMessage`
  - 无卡片 → 断言 `message/send` 打到输入路径，且 body 的 `metadata.kind` 仍在
  - `getTask` 在 v1.0 下发 `GetTask`，params `{id}`；`cancelTask` v0.3 下 `tasks/cancel` + `{id}`
  - 同源但路径越界（target `/tenantA`、卡片端点 `/tenantB`）→ 断言 POST 到 `/tenantA`，`/tenantB` 请求计数为 0
  - 总预算：`timeoutMs: 300` + 挂起的假服务端 → 抛 `A2aTimeoutError`，且总耗时 < 2s
  - 4xx 响应体 10KB 文本 → 错误信息被截断到 2KB 以内
  - 轮询遇到 `TASK_STATE_AUTH_REQUIRED` 立即返回，不等到超时
  - 超时 → 抛 `A2aTimeoutError`，message 含 `最后一次看到的状态` 与 `task_id=`
  - 4xx + `{error:{code:-32006,message:'…'}}` → `A2aRpcError.code === -32006`

- [ ] **Step 2: 跑测试确认失败**

- [ ] **Step 3: 实现**
  - 每个公开方法开头 `const { card, decision } = await this.ensureCard()`，并计算一次总 deadline（`Date.now() + timeoutMs`），发现/RPC/轮询共用 `remaining`。
  - `rpc(method, params, opts)`：URL 用 `decision.url`，版本用 `negotiateVersion(card)`，头带 `X-A2A-Version`；`redirect:'manual'`；4xx 先试 JSON-RPC body；非 JSON → `invalid JSON-RPC response`；嵌入 message 的 body 截断 2KB。
  - `send`：方法名取自 `methodsFor(version).send`；结果 `normalizeSendResult`；轮询用 `getTask`；停止条件=终态 ∪ `input-required`/`auth-required`/`unknown`；deadline 抛 `A2aTimeoutError`。
  - `sendForText`：`preferStream` 仅当 `card !== undefined && version==='v0.3' && card.capabilities?.streaming === true`。
  - `getTask`/`cancelTask`：`await this.ensureCard()`；方法名与 params 按 §3.4.4，params 一律 `{ id }`。
  - `-32601` 不换名重发；错误 message 附 `卡片声明 v<X>，已用方法 <Y>`，避免同一消息投递两次。
  - 错误统一经 `classifyError`（工具层用）。

- [ ] **Step 4: 跑测试确认通过**（含既有 smoke 全绿）

- [ ] **Step 5: 提交** `feat(client): negotiated RPC for send/stream/getTask/cancel with v1.0 adapter`
